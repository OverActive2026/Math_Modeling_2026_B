# 问题3两种辅助方式的启动时间优先试算

## 算法审计和补充搜索

上一版时间脚本只取功率全开这一边界点，没有真正搜索独立功率；而原六维优化器按辅助能耗优先排序，不能直接当作时间优化器。现在用 `q3_search_time_neighborhood.m` 在相同模型上逐片把功率从 1 降至 0.95 W/cm²，并要求候选在现有最快时刻之前达标。五个纯预热候选均未达标；五个协同候选也均未更快。协同第4片在原容差下曾出现非有限导数，是数值失败而不是物理失败；收紧容差并把最大步长减半后重算，最低平均温度仍约 −0.328 ℃，因此未更快。每次评价记录在 `time_neighborhood_search.csv`，该复核记录在 `time_numerical_check.mat`。

温度门槛是严格大于 0 ℃；代码的事件计算使用 0.01 ℃数值裕量。最早过温事件 33.5157465 s 是连续事件位置；33.5257465 s 是留 0.01 s 裕量、经完整约束复算的可行停热时长。更紧容差 `RelTol=1e-5`、`AbsTol=1e-9`、`MaxStep=0.025 s`、同一网格复算后，纯预热最低单片平均温度约 0.0143715 ℃，协同仍成功且达标时间 30.2436889 s，和原值相差约 0.0000774 s。

本轮还检查了题面规定的电荷、电流、电压和终点局部冰体积分数；协同候选的最低电压约 0.63082 V，累计电荷约 2.28673 C/cm²，最大局部冰体积分数约 0.11970，均在约束内。没有改变冰判据口径、加热面积、相变参数或网格。`gammaIce` 和 `kFreeze` 仍是未校准的试用值，且逐片 0.05 W/cm² 邻域搜索不能排除远处或协同变化带来的更快方案。

运行 `q3_optimize_startup_time` 可重新生成 `time_priority_candidates.csv` 和完整 MAT 轨迹；随后运行 `q3_search_time_neighborhood` 和 `q3_time_numerical_check`。MAT 中保留首次过温探测、调整停热时间后的复算结果和更紧容差的检查结果。
